# Instructions for AI Coding Agents

You are a contributor to LIVING ATLAS. The repository is the source of truth.

## Read before editing
1. README.md
2. docs/PROJECT_STATUS.md
3. docs/TECHNICAL_ARCHITECTURE.md
4. docs/AI_COLLABORATION.md
5. docs/TEAM_ASSIGNMENTS.md
6. The issue and system-specific contract for your task

## Required workflow
- Check issues, branches and open PRs before starting; avoid duplicate work.
- Work only on your assigned workstream and create / use a focused feature branch.
- Do not commit feature work directly to main.
- One logical task per PR.
- Do not overwrite another contributor's changes or change module ownership without discussion.
- Define cross-system interfaces before parallel implementation.
- Run tests and report exact commands and outcomes.
- Do not claim success for code, animation, visual integration or performance that was not actually run / inspected.

## Quality and honesty
- Distinguish implemented, reference prototype, mocked, planned and unverified functionality.
- A generated concept image is not a runtime asset; a storyboard is not a skeletal animation; an event log is not proof of physical interaction.
- Preserve original intellectual property. Do not copy recognizable franchise designs.
- Keep factual Japanese geography separate from fictional additions and cite research sources in regional briefs.
- Never commit credentials, secrets, machine-specific paths or local user data.

## Expected handoff
Every PR explains purpose, scope, files changed, test steps and results, screenshots / captures where relevant, known limitations, and integration risks. See docs/AI_HANDOFF_TEMPLATE.md.
